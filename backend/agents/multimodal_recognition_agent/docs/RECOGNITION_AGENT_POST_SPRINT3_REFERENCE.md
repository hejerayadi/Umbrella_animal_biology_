## 5. Runtime architecture and the LangGraph workflow

A real, compiled `langgraph.graph.StateGraph` (`workflows/graph.py`), built once per
`RecognitionWorkflow`, one request per `invoke`.

```
START
  → validate_image_and_text                       (VALIDATE)
  → plan_or_analyze_text                          (PLAN)      ← GPT call 1 of 2, optional
  → classify_with_mock_bioclip2                   (CLASSIFY)  ← the ONLY candidate source
  → evaluate_confidence                           (CONFIDENCE)← deterministic gate CLOSES here
  → validate_taxonomy_with_mock_gbif_and_ncbi     (TAXONOMY)  ← annotation only
  → explain                                       (EXPLAIN)   ← GPT call 2 of 2, optional
  → delegate_if_needed                            (DELEGATE)
  → finalize → END                                (FINALIZE)
```

*(The `CLASSIFY` and `TAXONOMY` node names are historical string literals; the provider
that actually runs is chosen by mode — `graph.py:38,41`.)*

Routing (`graph.py:_route`, `_PIPELINE`, lines 63–74, 245–252): every one of the six
pipeline edges is a **conditional** edge. The instant a node writes `error_code` into the
state, the graph jumps directly to `FINALIZE`.

**`finalize` is the single terminal builder** (`make_finalize_node`, `_build_agent_result`,
lines 77–160). All five outcomes — failure, uncertain, not-identified, identified,
delegation — converge there, which is why the output contract cannot hold on some branches
and not others.

Persistence: `graph.compile()` is called with **no checkpointer and no store**
(`graph.py:257`). `RecognitionState` is never logged, serialized or returned
(`workflows/state.py` docstring).

Providers are captured by the node factories, never carried in the state, so the state
stays a plain serializable data object (`graph.py:24-27`).

**Status: IMPLEMENTED AND VERIFIED** — `tests/test_phase4_gate.py:58-116` asserts a real
`StateGraph`; `tests/test_phase4_gate.py:117` onward asserts every node is independently
testable; `tests/test_phase4_gate.py:230` asserts the one terminal builder.

## 6. Input validation and the image-plus-text contract

`validation.py::validate_paired_request(instruction, context, config)` is the single entry
point (line 240).

### The contract

| Requirement | Enforcement |
| --- | --- |
| Instruction must be a **non-empty, non-whitespace `str`** | `EMPTY_INSTRUCTION` (`validation.py:249`) |
| `context` must be a `dict` | `MISSING_IMAGE` (`validation.py:252`) |
| Image lives under **exactly one key**, `"recognition_image"` | `config.RECOGNITION_IMAGE_CONTEXT_KEY` — a **constant, not a setting** (`config.py:27`) |
| Entry must be a `dict` with **exactly** `{data_url, filename}` | `MALFORMED_IMAGE_OBJECT` on any extra/missing key (`validation.py:88-100`) |
| `filename` must be an already-safe basename | `INVALID_FILENAME` — rejects `/`, `\`, `..`, drive-relative `X:`, control chars, `.`/`..`. **Never derives one** (`validation.py:50-76`) |
| Media types | `image/jpeg`, `image/png`, `image/webp` only (`config.ALLOWED_MEDIA_TYPES`) |
| Only inline base64 data URLs | `http://`, `https://`, `ftp://`, `file://`, `//`, and bare paths → `UNSUPPORTED_IMAGE_SOURCE`. **Nothing is ever fetched** (`validation.py:38, 117-134`) |

### The ordered decode path (cheap check before expensive one)

1. **Encoded-length guard** before any decode — `len(payload) > config.max_encoded_len`
   → `IMAGE_TOO_LARGE`. `max_encoded_len = 4 * ceil(max_bytes/3)`, deliberately **not**
   subtracting attacker-controlled padding (`config.py:264-276`).
2. **Strict base64** — `b64decode(validate=True)` → `INVALID_BASE64`.
3. **Decoded-size guard** → `IMAGE_TOO_LARGE`.
4. **Magic-byte detection** (`_MAGIC`, WEBP additionally checked for `"WEBP"` at offset 8)
   → `CORRUPT_IMAGE`; mismatch against the declared type → `MEDIA_TYPE_MISMATCH`.
5. **Header dimensions before pixel load** — area `> max_image_pixels` → `IMAGE_PIXELS_EXCEEDED`;
   below minimum → `IMAGE_TOO_SMALL`.
6. `probe.verify()`, then a **reopen-and-full-load** to catch truncation, with
   `LOAD_TRUNCATED_IMAGES` left at `False`.
7. A temporary, in-memory `ImageOps.exif_transpose(...).convert("RGB")` proving the later
   path is sound — it **never redefines `image_bytes`** and never feeds the hash.
8. `Image.DecompressionBombWarning` promoted to an **error** for the whole Pillow block,
   starting at the very first `open()` → `IMAGE_PIXELS_EXCEEDED`.

### Defaults (`config.py:from_env`)

`MAX_IMAGE_BYTES=10485760`, `MAX_IMAGE_PIXELS=25000000`, `MIN_IMAGE_WIDTH=64`,
`MIN_IMAGE_HEIGHT=64`. A config where `min_w*min_h > max_pixels` is refused at startup.

### Normalisation output

`NormalizedRecognitionInput` carries `instruction`, `image_bytes`, `context`, `media_type`,
`image_sha256`, `width`, `height`, `byte_size`, `filename`.

- `image_sha256` = SHA-256 over the **base64-decoded file bytes** — not pixels, not the
  data URL string (`validation.py:232-234`).
- The caller's context is **deep-copied**, then the image key popped from the copy, so the
  orchestrator's shared dict is never mutated (`validation.py:243-246`).

**Status: IMPLEMENTED AND VERIFIED** — `tests/test_validation.py` (68 tests), plus the
`test_api.py` HTTP-level refusals.

## 8. GPT-5 mini integration

**File:** `adapters/reasoning_llm.py`. **Selector:** `build_recognition_llm(mode, ...)` (line 771).

### Provider modes

| `RECOGNITION_LLM_PROVIDER_MODE` | Class | Behaviour |
| --- | --- | --- |
| `disabled` (**code default**) | `NullRecognitionLLM` | `plan()`/`explain()` return `None`; fully deterministic |
| `fake` | `FakeGPT5MiniProvider` | Offline, deterministic, exercises the real contract |
| `azure` | `AzureGPT5MiniProvider` | The approved Azure deployment |

The code default is `disabled`, **not** `fake`: "a fake brain must never switch itself on in
a running service" (`reasoning_llm.py:777-780`). An unknown mode raises
`AzureConfigurationError` listing the legal values. `azure` mode with missing variables
raises **naming the variables, never their values** (`AzureSettings.from_env`, lines 611-621).
The legacy `RECOGNITION_REASONING_LLM_ENABLED=true` still selects `azure` (`config.py:_provider_mode`).

### Exact maximum calls per request: **2**

`config.MAX_REASONING_LLM_CALLS_PER_REQUEST = 2` (line 112) — "Configuration may lower it.
Nothing may raise it."

- `RECOGNITION_LLM_MAX_CALLS_PER_REQUEST` is parsed by `_call_budget` with `ceiling=2`.
- A value **above 2 is clamped** to 2; **`0` survives as `0`** (explicitly fixed — the old
  `or` expression turned a configured `0` into the default `2`); a **negative or
  non-numeric** value is **refused at startup** (`config.py:150-175`).
- The budget lives on a `ReasoningBudget` **created fresh per request**
  (`nodes.py:159`), not on the adapter, so a long-lived adapter cannot accumulate calls.

The two roles are fixed:

| Call | Node | What the model may do |
| --- | --- | --- |
| 1 — **plan** | `plan_or_analyze_text` | Choose a subset of `ALLOWED_PLAN_STEPS` = `(classify_image, score_confidence, validate_taxonomy, explain)`, refine `intent`, and fill hints the rules left `None`. Step **order is imposed by the agent**, never by the model (`sanitize_plan`, line 379). |
| 2 — **explain** | `explain` | Phrase the already-computed evidence. |

**`MANDATORY_PLAN_STEPS = (classify_image, score_confidence)`.** A plan naming any forbidden
step, missing a mandatory one, carrying a non-enum `intent`, or a `top_k` outside `1..50` is
**rejected whole and never patched up** (`sanitize_plan`, lines 337-378).

**A failed planner forfeits the explanation call** (`nodes.py:462-471`): the explainer runs
only when `state.plan_source == "llm"`. Spending the second call after a contract failure
"would be a retry wearing a different hat."

### Grounding of the explanation

`explanation_is_grounded(text, request)` (line 411): rejects non-strings, empty text, text
over 2000 chars, **any binomial-looking name not in `candidate_names`** (with an
`_EXPLANATION_SAFE_WORDS` allowance for ordinary sentence openings), and any phrasing that
implies probability (`"% probability"`, `"probability of"`, `"certainty of"`, `"% confident"`,
`"% certain"`). Rejected text is replaced by the deterministic sentence.

A `_safety_footer` built from **runtime evidence** is appended **outside** whatever the model
wrote, so the model can never author the disclosure (`nodes.py:559-608`).

### What the model can never see

`PlanRequest` = `(instruction, has_image: bool, image_media_type, rule_intent)`.
`ExplainRequest` = ten already-computed scalar/text fields. Frozen dataclasses with **no
field for bytes, base64, a data URL, a vector, the request context or a credential** — "so
none can be passed even by mistake" (module docstring, lines 15-19; `PlanRequest` docstring,
lines 289-295).

### Timeouts and retries

| Setting | Value |
| --- | --- |
| Timeout variable | `RECOGNITION_LLM_TIMEOUT_SECONDS` — the **only** one |
| Default | **20.0 s** (`DEFAULT_REASONING_LLM_TIMEOUT_SECONDS`) |
| Validation | must be positive **and finite**; `0`, negative, NaN, infinity are refused at startup (`config.py::_timeout`) |
| SDK retries | `SDK_MAX_RETRIES = 0` (line 585), passed to the `OpenAI(...)` constructor |
| `store` | `False` on every `responses.create` call |
| `max_output_tokens` | `AZURE_OPENAI_MAX_OUTPUT_TOKENS`, default `400` |
| `reasoning.effort` | `AZURE_OPENAI_REASONING_EFFORT`, default `"low"` |

A previous second timeout variable (`AZURE_OPENAI_TIMEOUT_SECONDS`) was removed — it was
the one that actually took effect while the documented one was discarded
(`config.py:114-125`; regression: `tests/test_phase1_config_hardening.py:121,132`).
`max_retries=0` is deliberate: the SDK default of 2 "retried underneath the agent's own
no-retry rule", making one logical call up to three HTTP attempts and silently tripling the
effective timeout.

### Fallback behaviour

Every failure mode — timeout, auth error, empty body, unparseable JSON, schema violation,
forbidden step, any exception — returns `None` **exactly once** and the deterministic path
proceeds. `_call` logs **only `type(exc).__name__`**. `_extract_json_object` tolerates
fenced or prose-wrapped JSON — that is parsing, not retrying.

**Nothing is downloaded.** The local design was cancelled — it required a 2.66 GB
TreeOfLife text-embedding artifact on disk, and that exception was refused

### Scores

`classification_score` is a **ranking value, never a probability**:

| Mode | `recognition_mode` | `score_kind` |
| --- | --- | --- |
| `mock` | `mock_classification` | `deterministic_sprint2_test_score` |
| `remote` | `remote_bioclip2_open_domain_species` | `bioclip2_remote_zero_shot_ranking_score` |

`score_is_probability` is **`false` in both modes** — the remote value is a softmax over
~867k labels (`graph.py:200-205`). Scores are enforced to lie in `[0.0, 1.0]`, be
non-increasing and be distinct (`domain/ranking.py::assert_ranked_and_distinct`) — a
provider that breaks this **raises rather than being silently sorted**.

### Provenance

Derived from **what actually ran**, never from configuration: `is_mock` is computed from
`state.classification_mode`, the mode the provider that executed reports about *itself*
(`graph.py:176-179`). A real model version is never filed under `mock_provider_version` —
that key is `None` outside mock mode (`graph.py:189-192`).

### Label parsing

`parse_space_label` (line 320) splits the Space's `"Kingdom Phylum Class Order Family Genus
species (Common)"` string on a **single space**, never `str.split()`, because ranks can be
empty (a real reply contained a missing Order as a doubled space). A label that does not
parse is **dropped, never guessed at**.

### Failure behaviour

Every remote failure — sleeping Space, full queue, timeout, changed endpoint, broken client
— maps to the single controlled `ErrorCode.CLASSIFICATION_UNAVAILABLE` (`bioclip.py:_call`,
lines 445-501). Additional guarantees:

- **One deadline spans everything**: client construction, upload, queue wait, inference,
  result retrieval. `Client.predict()` is deliberately **not** used (it takes no timeout);
  the asynchronous `submit()` + bounded `job.result(timeout=remaining)` is used instead.
- **No retry loop.** One logical call, one attempt.
- An overrunning job is **cancelled** in `finally`, not abandoned.
- The temporary upload file is **removed in `finally`**; `download_files=False` so the
  Space's sample image is never fetched, and any returned sample path is deleted.
- Only `type(exc).__name__` is logged — "a remote error body can echo the request or the
  Space's internals."
- A malformed payload is a `CLASSIFICATION_CONTRACT_VIOLATION`, **not** an empty result:
  "the endpoint changed" and "this image has no match" must never look the same to the
  confidence gate.
- **Remote mode never falls back to the fixture oracle** (`tests/test_phase3_remote_bioclip.py:181,192`).

### Mock mode behaviour

Keyed by exact `image_sha256`. An unknown image returns an **empty list** → the gate reports
`not_identified`. "It can never attach a random biological label to an unknown photograph."
A malformed oracle → `CLASSIFICATION_FIXTURE_INVALID`, loaded **lazily** so a broken fixture
is a controlled request failure rather than a startup crash.

| Provider | Class | Verdict |
| --- | --- | --- |
| **GBIF** | `RealGBIFProvider` | **LIVE, IMPLEMENTED** — `https://api.gbif.org/v1/species/match`, no key required. **IMPLEMENTED BUT NOT LIVE-VERIFIED (this audit)** |

| GBIF (mock) | `MockGBIFProvider` | **MOCKED**, fixture-backed, disclosed as `mode: "mock"` |

| **IUCN** | — | **OUT OF SCOPE** — `.env.example`: "IUCN is out of scope for this agent." No code exists. |

Neither is *optional* in the sense of being skippable: whichever mode is configured, both
sources are consulted for every candidate, and each reports `available` / `matched`
independently.

### GBIF match semantics (`RealGBIFProvider.lookup`, lines 425-489)

- `matchType == "EXACT"` **and** an `int` `usageKey` → matched, identifier taken.
- `FUZZY` / `HIGHERRANK` → `available=True, matched=False, inconsistent=True` — **no
  identifier taken**.
- `NONE`, or an unrecognised future value → answered, no usable match.
- `EXACT` with no usable key → treated as unmatched rather than guessing.
- Any transport failure → `available=False, matched=False`. **An outage degrades; it never
  crashes.**

### NCBI semantics (`RealNCBIProvider.lookup`, lines 601-654)

- Query term is exact-quoted: `"<scientific name>"[Scientific Name]`, `retmode=json`.
- `tool` and `email` are sent on every request (NCBI Entrez guidelines) and are **read from
  configuration, never hardcoded, never logged**.
- Exactly one id → matched. **More than one id → `inconsistent=True`, no identifier taken.**
- Zero ids / non-dict payload → answered, unmatched.

### Rate limiting — pacing, not retrying

| Constant | Value |
| --- | --- |
| `NCBI_PUBLISHED_LIMIT_WITHOUT_KEY` | `3.0` (what NCBI documents) |
| `NCBI_REQUESTS_PER_SECOND_WITHOUT_KEY` | **`2.0`** (what the agent actually sends at) |
| `NCBI_REQUESTS_PER_SECOND_WITH_KEY` | `10.0` |

The unkeyed rate is deliberately **below** the published cap: at a measured 2.86/s, 1
request in 8 was still rejected, because "the rate NCBI observes is not the rate we send
at" (`taxonomy.py:494-513`). `_RateLimiter` (line 516) uses `time.monotonic` — never wall
clock — injects `monotonic`/`sleep` for testing, and **holds its lock across the wait** so
waiting threads cannot wake and burst together. `acquire()` is called **before** sending.
Four lookups produce exactly four requests.

### Startup refusal

`TAXONOMY_PROVIDER_MODE=real` **without** `NCBI_TOOL` and `NCBI_EMAIL` raises `ConfigError`:
"Refusing to start rather than calling NCBI unidentified" (`taxonomy.py:373-378`; regression
`tests/test_phase1_config_hardening.py:328`). Real mode **never falls back to the fixture**
(`test_phase1_config_hardening.py:350,397`).

### The annotation-only contract

The taxonomy node runs **after** the confidence gate has closed (`graph.py` `_PIPELINE`).
Neither source can select, reorder, rescore or change a decision — it may only annotate
candidates the classifier already produced (`nodes.py:288-296`). The primary species is
re-looked-up **by `species_id`**, so an enrichment cannot substitute a different species
(`nodes.py:342-352`). A missing identifier **stays `null`, never inferred**.

### Status values, kept deliberately distinct

| Status | Meaning |
| --- | --- |
| `mock_verified` | The **fixture** had both identifiers — nothing was checked live |
| `verified` | **Live** GBIF **and** live NCBI both matched |
| `partial` | Exactly one source supplied an identifier |
| `unverified` | Neither did |

`domain/models.py:TaxonomyStatus` carries all four. "The two are deliberately distinct
values so a response can never be misread as live when it was mocked, or vice versa."

### Real mode ships no name catalogue — by design

`RealTaxonomyProvider.known_names()` returns `{}` and `resolve_name()` returns `None`
(lines 736-767). There is no offline catalogue in real mode, and inventing one would mean

## 12. Error handling, resilience, privacy, secrets, image protection, logging

### Structured failure on every path

`ErrorCode` (`domain/errors.py`) defines 18 codes across four groups: paired-input
contract (4), image transport (4), image content (5), classification (3), taxonomy (1).

`RecognitionError.__init__` takes **an `ErrorCode` and nothing else** — "There is no
parameter through which a data URL, a filename, a base64 fragment or a decoded byte could
be attached to an exception." The message is derived from the code alone, so two requests
failing the same way produce **byte-identical text**. `Exception.args` therefore holds only
the fixed message.

Nodes **never raise**: a `RecognitionError` is caught and written into the state as
`error_code`; the router jumps to `finalize` (`nodes.py:_failed`, `graph.py:_route`).

### The HTTP boundary never returns a 500

`api.py::execute` wraps `_agent.run` in a bare `except Exception`. It returns
`AgentResult(status=FAILED, output={"error_code": "INTERNAL_ERROR", "error": <fixed text>})`
— **deliberately not an `HTTPException`**, because "the orchestrator's router expects one
schema back every time" and a FastAPI `{"detail": ...}` body would break it.

`INTERNAL_ERROR_MESSAGE` is fixed, data-free and **identical for every unexpected failure**:
"the whole point is that two different exceptions produce byte-identical text." A
`uuid4().hex` correlation id ties the caller's failure to the logged one **without putting
anything about the failure into the response**. Only `type(exc).__name__` is logged.
(Regression: P7-F1 / P7-F2 — this path used to interpolate the exception into the body.)

### Image-data protection — exclusion by construction

`NormalizedRecognitionInput.image_bytes` and `.context` are both
`Field(repr=False, exclude=True)`:

- `repr=False` → out of `repr()` and `str()`;
- `exclude=True` → out of `model_dump()` / `model_dump_json()`, **applied at the serializer
  level so a caller cannot switch it off**.

Stripping the image key out of the retained context is **defence in depth on top of that,
not the guarantee itself** (`domain/models.py:12-30`). `model_config` is
`extra="forbid", frozen=True`.

`RecognitionState` is never logged, serialized or returned; no checkpointer persists it
(`state.py` docstring).

### Secret handling

- `config.py` **deliberately does not load a `.env` file** — "keeping that responsibility
  out of here means no credential can ever be read, cached or printed by this codebase."
- **No credential enters a configuration object.** `RecognitionConfig` has no base URL, no
  key, no deployment name. `AzureSettings` reads them at lazy-construction time and holds
  the key in memory only.
- Missing-variable errors **name the variables, never their values**
  (`AzureSettings.from_env`; `tests/test_azure_provider.py:134`,
  `test_phase1_config_hardening.py:448,464`).
- `.env.example` is committed with **names and empty placeholders only**, and explicitly
  says `NCBI_EMAIL` must be left empty there because the file is committed.
- The agent `.env` is **git-ignored and untracked** — confirmed in §1.

### Logging discipline

`api.py::quiet_dependency_http_loggers()` pins `httpx`, `httpcore`, `urllib3` and `openai`
to `WARNING` at service startup. The reason is specific and documented (P7-F3):

- at INFO, `httpx` logs the full Azure request URL, carrying the endpoint host and resource
  name;
- at DEBUG, `httpcore`/`urllib3` additionally log the deployment name and the **NCBI email,
  percent-encoded in the Entrez query string** — "which is why a leak scan looking for
  `name@host` reports clean while the address is sitting in the log."

The Azure API key is unaffected either way: it travels in a header, never in a URL.
Pinned to `WARNING` so an operator raising the ROOT level for diagnosis does not silently
start writing endpoints and an address to disk. **Scope limit:** this applies at the HTTP
entry point only — code importing `RecognitionAgent` directly (the smoke scripts do) keeps
its libraries' own levels.

The agent's own loggers record decisions only: mode, provider, counts, dimensions, byte
size, decision, alignment, margin — never a pixel, a payload or a context value.

### Resilience summary

| Property | Mechanism |
| --- | --- |
| No retry anywhere | `SDK_MAX_RETRIES = 0`; single bounded `job.result()`; NCBI paces rather than retries |
| Every provider bounded | Azure 20 s, remote BioCLIP 90 s (one deadline spanning everything), GBIF/NCBI 10 s |
| Job cancellation | An overrunning BioCLIP job is cancelled in `finally` |
| Temp-file hygiene | `_remove_quietly` in `finally`; `download_files=False` |
| Taxonomy outage | Degrades with a warning, **never fails the request** |
| LLM outage | Deterministic plan and explanation stand |
| Classifier outage | Controlled `CLASSIFICATION_UNAVAILABLE` — never fixture fallback |
| Request isolation | Budget is per-request; no state survives an `invoke` |

## 4. Protected contracts Sprint 4 must not break

1. **The shared schema.** `AgentRequest(instruction, context)` /
   `AgentResult(status, target_agent, prompt_to_target_agent, output)` / the four
   `AgentStatus` values.
2. **The seven output keys, exactly.** `species`, `species_id`, `gbif_id`, `ncbi_taxid`,
   `recognition`, `recognition_candidates`, `recognition_provenance` — asserted as **set
   equality**, so an addition fails as loudly as a removal.
3. **The failure shape.** `{"error_code", "error"}` on every failing path, with fixed,
   data-free messages derived from the code alone.
4. **Never an HTTP 500.** `POST /execute` always returns the shared schema, including on
   an unexpected exception.
5. **One image key.** `context["recognition_image"] = {"data_url", "filename"}` — a
   constant, not a setting; extra keys are `MALFORMED_IMAGE_OBJECT`.
6. **Both inputs mandatory.** One image **and** one non-empty text instruction.
7. **The classifier is the sole source of species candidates.** No node, no text, no LLM,
   no GBIF and no NCBI may add, promote, reorder or rescore a taxon.
8. **The confidence gate is deterministic and closes before taxonomy runs.**
9. **Text may downgrade, never promote.** A conflict yields `uncertain`.
10. **A missing identifier stays `null`** — never inferred, never borrowed from a sibling.
11. **The two-call GPT ceiling**, with a per-request budget, no retry, and a rejected plan
    or ungrounded explanation falling back to the deterministic path.
12. **`score_is_probability: false`** in both modes, and `mock_verified` ≠ `verified`.
13. **Provenance derives from what actually ran**, never from configuration.
14. **No factory ever degrades to a mock** outside mock mode.
15. **Image bytes and shared context are excluded by construction** (`repr=False,
    exclude=True`) and never reach a log, an exception, a prompt or a response.
16. **`uncertain` and `not_identified` are completed outcomes**, not service failures.
17. **`finalize` is the only builder of an `AgentResult`.**
18. **Zero retries at every external boundary**; every provider call is bounded.
19. **Delegation names a capability and stops.** Recognition never calls a peer.
20. **No vector search, no embedding, no similarity, no Qdrant** may re-enter the runtime.
